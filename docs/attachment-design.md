# 主题附件

仅主题首帖支持上传和编辑附件列表，回复的新建和编辑均不支持传附件；已有回复附件保留并按原有权限提供下载。附件独立于正文图片，正文下方显示文件名、大小和下载链接，不做在线预览。

## 发布设置

后台「发布设置」区分图片与普通文件附件。旧的 `uploadControl` 字段继续控制图片；新增 `attachments` 设置：

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `enabled` | `true` | 开关仅限制新增附件 |
| `maxFileSizeKb` | `5120` | 1–51200 KiB |
| `maxFilesPerPost` | `5` | 1–20 |
| `extensions` | `.pdf`, `.txt`, `.zip` | 当前支持这三种类型的子集；空列表禁止新增 |

文件名、实际读取大小及内容均在服务端校验；PDF/ZIP 检查签名，TXT 要求 UTF-8 且不含 NUL。文件名不能包含路径分隔符或控制字符。签名校验不是病毒扫描，下载始终强制作为附件返回。

上传在读取请求体前检查附件权限、冷静期和每日额度，同一次请求复用账号策略。multipart 流式读取，文件内容最多读取配置上限加一个字节；整个请求另留 1 MiB 表单开销。已验证的缓冲区直接交给数据库存储，避免二次完整读取。绑定附件在帖子事务中一次批量锁定、校验，再对尚未绑定的文件执行一次条件更新并核对影响行数。

附件上传权限在后台「等级设置 → 等级限制」逐级配置 `allowAttachmentUpload`，默认成员及以上允许、新用户禁止；高等级不能比低等级更严格。附件类型使用可独立增删的输入项配置。

附件沿用账号可写检查、注册上传冷静期及每日上传次数，与图片、头像共用计数。原有角色账号的上传额度和冷静期豁免保持不变；附件开关、等级权限、文件类型、大小和数量仍生效。保留本帖原有附件不重新执行新增上传策略，管理员收紧设置不阻止旧内容编辑。

## 数据与存储

- `attachments` 位于论坛数据库，保存上传者、原文件名、大小、存储对象名和归属帖子。
- `posts.attachments` 保存服务端生成的附件显示元数据，与正文一同保存；客户端只传 ID，不能指定文件名、大小、对象位置或归属。
- 主题创建/编辑在原有首帖事务中绑定附件。每个附件永久归属最多一个帖子；移除仅修改当前附件列表，不物理删除已经归属帖子的文件，也不会允许其他帖子重新占用。
- 上传先写文件存储，再创建附件记录。文件数据库与论坛数据库可以不同，不依赖跨库事务或外键；附件记录创建失败会尽力清理文件并记录失败。
- **当前版本普通附件固定使用数据库文件存储**，与 `storage.driver` 指定的图片存储分开。因此图片采用公开 S3/CDN 时，附件仍在数据库中私密保存。此前提案中的独立私有 S3 bucket 未作为本次存储方式；当前没有附件 S3 直传或预签名下载。
- 普通附件对象使用保留的 `attachment-` 前缀，现有 `/file/img/*filename` 路径拒绝读取；只能经附件下载接口访问。

该实现沿用审核的当前内容模型：先审后发模式下，帖子及其附件一起隐藏，审核通过后一起可见；先发后审模式与正文一致。审核不会将文件从一个帖子移到另一个帖子。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/file/attachments/policy` | 当前用户的附件上传策略 |
| POST | `/file/attachments` | multipart，`file` 字段，返回 `id/filename/size/url` |
| GET | `/file/attachments/:id` | 下载，实时检查内容权限 |
| DELETE | `/file/attachments/:id` | 上传者取消尚未绑定的文件 |

上传和取消只接受登录会话并检查账号可写状态。未绑定文件只有上传者可下载。绑定后需检查附件仍在帖子当前列表、帖子及主题未被删除，以及分类 ACL 和内容隐藏状态；作者/管理员的访问例外依照相应内容状态处理。不存在与无权访问统一返回 404。已发布主题被手动屏蔽后，作者也不能下载其附件；分类管理者的例外与主题页面一致。

下载使用 `application/octet-stream`、安全编码的 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Cache-Control: private, no-store`，不返回底层对象地址。

主题写入接口支持可选 `attachmentIds`：缺失或 `null` 保留既有列表，空数组明确移除全部；重复、跨用户、跨帖引用均拒绝。编辑接口接受 `version`，主站发送读取时版本，冲突时保留编辑器内容并提示刷新。旧 Agent 客户端省略附件字段时仍保留现有附件；未新增 Agent 附件上传入口。回复写入接口拒绝非空 `attachmentIds`，省略、`null` 或空数组均不修改已有回复附件。

## 草稿与清理

主题本地草稿保存已上传附件的引用和编辑版本；服务器主题草稿的附件直接绑定首帖。上传中和上传失败尚未处理时禁止提交，失败可重试或移除。

未绑定文件保留 14 天，与本地草稿保留期一致，之后由现有周期任务分批回收。清理和绑定使用条件写入避免并发误删：清理先删除未绑定记录，若帖子事务抢先绑定则清理失败；若清理抢先成功则帖子保存回滚。跨库文件删除失败会记日志，可能留下无法访问的孤立存储对象，不引入持久化恢复任务。

已绑定后移除的文件不自动物理回收，避免编辑和历史草稿中的引用竞争；只有再次添加到原帖子并通过当前新增策略时才重新可下载。

## 迁移与验证

应用迁移 28 为旧发布设置补齐附件默认值，不改图片设置；新安装使用同样默认值。结构迁移注册附件表和帖子的附件 JSON 字段。

应用迁移 29 将旧 `attachments.minTrustLevel` 转为各等级的 `allowAttachmentUpload`，保留原阈值对应的权限和已明确设置的权限；不再在发布设置中编辑等级数值。

新增自动化覆盖文件类型/大小/文件名、等级、跨用户/跨帖引用、权限变更、隐藏回复、旧客户端保留、版本冲突、取消上传、HTTP 下载头、原始文件路径拒绝访问，以及配置迁移。浏览器用例覆盖桌面/移动端上传失败重试、提交与显示。

数据库自动化在 SQLite 环境执行；MySQL、PostgreSQL 与生产部署尚需在对应环境验证。当前版本不需要配置或验证 S3 附件 bucket。
