# 登录与安全记录

## 记录与访问

沿用 `user_auth_token_logs`，新增认证方式、OAuth provider、结果和内部原因。
既有 `generate` 记录保留，界面显示为登录；既有空结果兼容为成功。
认证成功以会话创建为准，每次只写一条 `login_success`，续期和活跃更新不记登录。

密码登录失败、OAuth 回调失败、MFA 挑战和挑战失败采用 `user_id = 0` 表示未关联
账号，不保存尝试用户名或邮箱，也不因已通过第一因素就关联到某个用户。
已登录用户的安全变更失败可以关联当前账号。密码、MFA 密钥、验证码、恢复码、
令牌和登录加密载荷均不进入审计字段。

个人设置的登录设备页附有安全记录，查询强制限定当前用户 ID，忽略请求中的其他
用户 ID，并隐藏内部原因。管理员用户管理权限下的登录记录页可查询所有事件，
筛选账号 ID、认证方式、结果和日期。未知账号记录仅管理员可见。

## 容量与清理

失败及挑战按每进程内存窗口控制写入：每 IP 每分钟最多 10 条，密码登录失败还按
尝试账号的 HMAC 摘要每分钟最多 10 条，全局每分钟最多 1000 条。摘要采用每进程
随机密钥，仅用于内存预算，不写入数据库。预算表容量最多 4096 个键，过期窗口随请求清理。成功登录和安全操作成功
不采样，不引入异步持久化任务。

沿用现有 90 天保留和每批 500 条清理。日志写入失败输出运行错误，不撤销已经
创建的会话。分页大小上限 100，默认 20。

## ID 分页

日志按 `id DESC` 展示，下一页使用上一页最后一条实际记录的 ID 作为边界，查询
`id < cursor` 并取 `pageSize + 1` 条，额外一条用于判断是否还有下一页。第一页不带
ID 边界，不查询总数，不使用 SQL `OFFSET`，也不把最大 ID 当作记录总数。

页面保留已访问的 ID 边界以支持上一页；修改筛选、刷新或切换账号后回到第一页。
不显示精确总页数，也不支持任意页码跳转。ID 间断、删除和新增日志不会因按页码
计算偏移而造成重复；时间倒退不会改变翻页顺序。

用户、结果、认证方式分别使用与 ID 的联合索引，时间索引保留用于过滤和清理。
成功结果兼容历史空结果时，分别进行两次有界查询后按 ID 合并，避免 `OR` 分支
导致全量排序。复杂组合筛选的耗时仍取决于过滤选择度，未进行生产数据量压测。

IP 来源使用 Gin 的 `ClientIP()`，受信任代理必须在服务入口显式配置，默认不信任
任意转发头。部署多个服务进程时，各进程预算独立，不能将其当作跨节点防攻击限流。
