# 双因素认证运维与使用

双因素认证使用标准 TOTP 验证器（6 位、30 秒）和 10 个一次性恢复码。支持密码登录、
OAuth 登录；第三方身份通过后仍需本地第二因素，未通过时不会建立站内登录会话。

## 部署配置

只使用 `[app].secretKey`（兼容未配置新字段时读取旧 `signingKey`），通过 Go 标准库 HKDF-SHA256 和双因素专用用途标识派生
32 字节 AES 密钥，不需要其他密钥配置。配置生成器使用 `crypto/rand` 生成 32 个
随机字节，编码为 43 位无填充 Base64URL，提供 256 位随机性；随机源失败时不降级
到时间、进程号等可预测信息。MFA 严格校验 Base64URL 格式和解码后的 32 字节长度。

密钥仅存服务端私有配置，不放在公开设置、数据库或源码中，不能使用口令替代。
已绑定用户后应备份并保持系统密钥不变；重命名配置时保留原值，不提供在线轮换。数据库仅保存 AES-GCM
认证加密后的 TOTP 密钥和恢复码 SHA-256 摘要。配置缺失或密钥损坏时拒绝验证，
不得自动跳过第二因素。服务器应保持时钟同步。

派生方式参考 [Go 标准库 HKDF 文档](https://pkg.go.dev/crypto/hkdf)。

挑战、待确认绑定和验证限额统一使用 sharedcache，每类最多 10000 条。当前后端仅为
进程内存，原子更新也只保证当前进程内并发安全；未来共享后端必须提供对应原子操作。
挑战和待确认绑定分别 5 分钟、10 分钟过期；服务重启后重新登录或
重新绑定。第一版用于单实例，不支持跨实例挑战。每挑战最多 5 次尝试；账号和 IP
分别限制为 5 分钟内最多 10 次、100 次验证，换挑战不能清零账号限制。

## 用户流程

账号设置中输入账号密码后绑定验证器，扫码或手工输入密钥，再输入验证码确认。
服务端返回标准 otpauth URI，浏览器使用 qrcode.react 生成二维码；进入扫码步骤后隐藏密码框。
确认前不生效。启用、关闭和重新生成恢复码均撤销所有设备的登录，并失效未完成挑战；
恢复码在当前页面显示一次，可下载保存，保存后返回登录。验证码不能重复使用。

这些操作不使用显式业务事务，进程内使用固定 256 段锁串行化同一用户的 MFA 操作。
先递增会话版本并撤销会话，再修改 MFA 数据；部分失败仍刷新缓存，使旧会话失效。
启用最后写入因子；关闭最后删除因子；恢复码替换先写入新码，再删除旧码。
写入或清理失败时可以重新操作；已消费的验证码不恢复，需要另一个恢复码或下一轮动态验证码。
关闭过程中恢复码已删除但因子删除失败时，使用验证器重试，丢失验证器则由管理员重置。
锁仅适用于当前单实例，未来共享后端需要配套跨实例并发控制。

第三方登录账号需先在个人资料绑定并验证邮箱，然后通过现有重置密码流程设置本地
账号密码，之后即可绑定 MFA。普通 OAuth 回调不能作为账号安全设置的密码复验。
密码重置不关闭已有 MFA，拿到邮件链接也不能跳过登录第二因素。

恢复码每个提供 128 位随机性且只能使用一次，旧码在重新生成后整体失效。丢失全部
第二因素时应由站点管理员核验身份后处理；第一版没有自助邮件绕过或无审计的自动恢复。

## 管理员恢复

MFA 登录先原子消费验证码或恢复码，再创建会话，不使用业务事务。
若会话创建失败，已消费的码不会恢复：恢复码需换另一个，动态验证码需等待下一轮。

完整管理员可在后台「用户 → 编辑 → 账号设置」查看双因素认证状态并重置。
操作前核实用户身份，填写原因并二次确认。普通用户管理员不具有此权限，
管理员不能使用该入口重置自己的 MFA，应在个人设置中使用密码和第二因素关闭。
重置删除验证器与恢复码，撤销登录会话和未完成的登录挑战，记录操作者 ID、
目标用户 ID 与原因。密码不变，用户重新登录后可再次绑定验证器。不提供 CLI 命令。
重置不使用业务事务：先使会话版本失效，再撤销会话、删除恢复码和临时状态，最后删除因子并记录审计。
任一步失败会返回错误；重复执行可继续完成清理，部分失败也会刷新账号缓存。
