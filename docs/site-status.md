# 统一站点状态检测

浏览器主站与管理后台共用宿主层检测器，每 30 秒请求 GET /api/forum/status；隐藏标签页暂停，重新可见或恢复联网时检查。请求不重叠，10 秒超时取消。旧 GET /api/forum/unread-status 保持登录要求及原响应兼容，默认主站不再单独轮询它。

公开状态包含 deploymentId；登录用户还附带 unread（沿用原通知、私信、举报范围规则）。游客不查询未读数据，未读计算失败不会阻断版本检测。响应禁止缓存，版本计算不查询数据库，没有新增表、事务、WebSocket 或任务。

初始服务端 HTML 注入部署标识，浏览器以它为固定基准，不随 SPA 页面导航更新。标识由后端版本、提交、构建日期及 Vite manifest 的 SHA-256 生成并在进程内缓存，同一构建的多实例一致；生产前端嵌入 Go 二进制，更新资源需要重新构建后端。自定义构建应注入 buildinfo.BuildDate/Commit，避免相同元数据与相同资源下的后端变化无法识别。Vite 开发页面没有该 meta，以首次成功状态响应为基准。

部署变化显示刷新/稍后提示，同一版本在当前页面选择稍后后不再提示；不自动刷新。主站编辑器原有 beforeunload 保护继续生效，后台刷新按钮另有未保存内容确认。资源动态导入失败显示刷新重试入口，检测失败不冒充更新。提示挂载在页面根节点之外，页面懒加载失败时仍可操作；若入口 JS 自身无法加载，无法依靠尚未运行的 JS 显示提示。

这是升级提醒，不是 API 兼容协议。滚动发布期间应保持接口兼容并保留旧静态资源；本功能首次部署前已经打开的旧客户端没有检测器，需要先刷新一次。


## 首页新主题提示

状态接口附带 `publicMaxTopicId`，仅统计主分类对所有人开放、已发布且未屏蔽/删除的主题。首页主列表以页面加载时的 ID 为基准，轮询值更大时显示“有新主题，点击查看”；不计算数量、不自动插入，不在分类、搜索、详情或后台显示。点击后重新加载当前排序的第一页，成功后更新基准。

最大 ID 使用进程内单条缓存，复用 sharedcache 的并发合并与失效保护。主题列表失效、权限组或系统组变更时同步失效，下次读取重建；24 小时过期兜底。查询失败时省略字段，不将错误当作 0。没有新增轮询、数据表或事务。多实例部署的失效只影响当前进程，需要额外共享失效机制才能实时同步其他实例。

这是最大 ID 的新旧提示：旧 ID 的草稿延迟发布、旧主题重新开放，不保证触发；删除最大 ID 造成回落不会提示。权限受限主题不会参与比较。
