# 缓存边界

## 固定本地缓存

`app/bundles/localcache` 用于明确只在进程内存在的缓存，不读取共享缓存后端配置。
当前包括主题运行时计算结果、站点统计和 SEO XML。静态资源 gzip 仍使用自身的本地实现。
用户活跃时间和浏览量是写入缓冲，继续由各自的业务服务管理。

## 可替换业务读缓存

`app/bundles/sharedcache` 封装可替换后端的业务读缓存。当前仅实现 memory，
仍是每个进程独立缓存，不能据此宣称已有集群一致性。

接入范围：分类、话题列表、页面配置、敏感词配置、用户信息与公开资料、角色权限、
访问组成员与授权、未读状态、举报状态、徽章定义、会话访问权限。

```toml
[cache]
driver = "memory"
```

缺省值为 memory，启动时校验并固定配置，运行期间的配置文件变化不影响后端选择。
修改后重启。未知 driver（包括尚未实现的 redis）会被拒绝，
不会静默回退为内存。固定本地缓存不受此配置影响。

每个 Cache 使用稳定且唯一的 Name 标识命名空间。不同值类型、业务或数据来源不能
共用命名空间。当前 memory 后端的每个 Cache 对象独立持有条目；自定义 Resolver
也保持各自独立缓存。未来远程后端需为不同数据来源明确划分命名空间。

Backend 接口负责读写、TTL、删除、命名空间清空、前缀删除及仅更新已有条目。
NewWithBackend 支持注入后端。memory 复用 localcache，保留原有容量与 TTL。
GetOrLoadE 返回读取/加载错误；缓存填充失败时返回已加载数据并记录错误。
写入和失效方法返回错误并记录日志，现有调用延续不返回错误的业务行为。
singleflight 只合并当前 Cache 对象内同一个 key 的加载。只跟踪正在进行的加载，
完成后清理记录。单 key 写入/失效只解除该 key 的加载关联，前缀删除只影响匹配的
key，清空影响全部 key；失去关联的旧加载不会回填，也不会阻塞新的加载。
即使更新时条目不存在，也解除同 key 的加载关联，避免数据库更新前的旧查询回填。
后端初始化返回错误，失败后允许重试。
这些保护不提供跨实例并发保证。

失效完成前已开始的请求仍可能返回它读到的旧结果；失效保证的是旧结果不回填、
失效完成后新请求不加入旧加载。这不是中断在途请求或即时撤销授权的保证。
权限敏感写操作若要求执行时重新确认授权，需要在对应业务入口单独校验。

## 专用存储

登录会话继续由 authsessionservice 的 authCache 接口管理，保留用户撤销、
generation 和续期语义。验证码继续由 base64Captcha.Store 接口管理，保留
过期与一次性消费语义。它们当前仍为内存实现，不受 cache.driver 控制。
未来分别增加后端工厂与配置，不接入通用读缓存。

## 后续 Redis 适配

增加后端工厂分支及 Redis 配置，使用明确的命名空间和序列化格式。命名空间清空、
前缀失效和进行中的加载应设计为跨实例安全；不要依赖当前进程的加载跟踪。
用户资料中的 UpdateIfPresent 必须避免与删除并发时重新创建条目。
会话撤销的生效时限、验证码原子消费及共享后端故障行为需要分别定义和测试。
Redis 的内存/淘汰策略不能直接等同于 memory 的 MaxEntries。

## 内存后端验证

可重复运行的基准与并发回归测试位于 `app/bundles/sharedcache`：

```sh
go test -race ./app/bundles/sharedcache -count=30
go test ./app/bundles/sharedcache -run '^$' -bench '^BenchmarkCache' -benchmem -cpu=1,8
```

并发压力用例同时运行 32 个读协程（合计 16,000 次读取）与 1,000 次 key 删除、
前缀删除和清空，检查写入结束后的最终值与加载记录清理。API 回归测试覆盖已预热
角色权限的撤销/删除、配置保存后刷新，以及配置写入失败时不清缓存且返回失败。
主题保存、主题发布和 OIDC 设置的写入失败分支也覆盖在 API 测试中。

本机 Apple M1 的两次 8 并发基准结果：shared 命中约 440–475 ns/op、零分配，
local 命中约 421–431 ns/op。1% 主动删除时约 0.01 次模拟加载/op。
2,048 条目满缓存的无匹配前缀删除约 112–114 us/op，复杂度为 O(n)，并会持有
该 Cache 的锁。当前未读缓存容量为 2,048；扩大容量或提高失效频率前需要重新评估。

8 并发混合负载（2,048 条目，每 100 次操作执行一次匹配前缀失效）的两次结果为
1.54–1.60 us/op，约 0.0099 次模拟加载/op；相同计时方式的纯读为 0.49–0.53 us/op。
混合基准还按对数桶记录读取延迟的 p95 上界；其值受调度影响，不能当成精确 p95
或服务延迟承诺。当前容量下没有模拟回源放大，但前缀扫描有可测量的吞吐成本。

上述基准使用模拟加载，测量的是缓存封装成本，不代表 HTTP 延迟、真实数据库吞吐量
或 Redis 性能。业务权限读取只加载 effective=1 且未软删除的权限记录。
