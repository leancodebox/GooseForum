# 新增功能验收

本地后端与页面入口为 http://localhost:5234/ 。使用一个管理员和两个普通测试账号；涉及封禁的操作只对测试账号执行。需要权限的页面在未登录时跳转到登录页，登录后返回原地址。

## 入口与操作流程

| 功能 | 地址 | 正常流程 |
| --- | --- | --- |
| 用户提及 | http://localhost:5234/publish 和任意主题详情页 | 输入 `@` → 选择用户 → 发布主题或回复 → 被提及账号在 http://localhost:5234/notifications 查看并打开通知。 |
| 双因素认证 | http://localhost:5234/settings?tab=account | 输入密码 → 绑定验证器 → 输入 TOTP 确认 → 下载恢复码 → 重新登录 → 通过第二因素后进入站点。 |
| 本地草稿 | http://localhost:5234/drafts | 在发布或回复框输入 → 自动保存唯一草稿 → 重新进入时选择恢复或丢弃 → 完成发布后对应草稿移除。 |
| 账号限制 | http://localhost:5234/admin/users | 选择测试用户 → 设置禁言或封禁及原因、期限 → 测试账号验证限制 → 管理员解除 → 测试账号重新登录恢复。 |
| 登录与安全日志 | http://localhost:5234/settings?tab=sessions 和 http://localhost:5234/admin/auth-logs | 进行登录、安全设置或封禁操作 → 查看日志 → 按结果、方式、时间筛选 → 翻页；个人页只显示本人记录。 |
| 注册限制 | http://localhost:5234/admin/settings/security 和 http://localhost:5234/login?mode=register | 保存注册开关、邮箱域名、各项限额 → 使用新账号注册 → 收到邮件并验证 → 登录；OAuth 首次注册遵守同样政策。 |

## 提及

1. 分别验证主题、普通回复、定向回复的候选选择、发布和通知跳转。
2. 代码块、行内代码、已有链接中的 `@` 不产生提及；重复提及同一个用户只发一次通知，自提及不通知。
3. 待审核内容通过审核后才通知；编辑已发布内容只通知新增加的收件人。
4. 用户改名后仍按用户 ID 链接正确账号；删除账号后安全显示文字。旧内容保持旧语法行为，编辑升级时不会重发旧提及。

## 双因素认证

按 [部署配置](two-factor-authentication.md) 只从 `[app].signingKey` 派生专用密钥，无需新增配置。已有绑定必须保留原 `signingKey`，配置错误时应显示不可用并拒绝验证。

1. 确认前取消绑定，账号仍未启用 MFA。确认成功后旧设备会话全部失效，保存恢复码再返回 http://localhost:5234/login 。
2. 密码和 OAuth 登录都应先进入第二因素挑战；错误、过期或重复验证码不能建立登录会话。
3. 用一个恢复码登录，再次使用同一码失败；重新生成恢复码后旧码和未完成挑战失效。
4. 关闭 MFA 后重新登录无需第二因素；密码重置不会关闭已启用 MFA。
5. 完全丢失第二因素由管理员核实身份后使用 CLI 恢复，见部署文档；操作留下安全日志。
6. 启用 MFA 后绑定新的第三方登录方式需要输入验证码或恢复码；发起绑定后退出登录、切换会话或修改账号安全版本，旧绑定回调不能继续成功。

## 本地草稿

1. 同一账号、编辑类型和对象只留一份草稿；标题或正文有内容才保存，只有分类或回复目标变化不保存。清空标题和正文后删除当前草稿；加载时清理旧空白、过期及重复副本。
2. 进入时出现恢复提示，选择恢复后继续编辑，选择丢弃后删除草稿并不再提示。选择未决时不得覆盖草稿或发起提交；发布成功后不误删继续输入的内容。
3. 在长主题中保存对后段楼层的定向回复，回到主题第一页恢复；目标未加载时先核验，再恢复正确作者和楼号。
4. 网络异常显示可重试；目标删除、隐藏或无权限时禁止恢复，草稿保留，目标重新可用后可恢复，也可主动丢弃。
5. 切换账号或退出后不显示前一个账号的草稿；检查多标签页及过期清理，别的对象草稿不能被当前对象清理操作误删。

## 账号限制与权限

1. 禁言账号可以阅读和使用账号安全功能，不能发主题、回复或执行受限互动。
2. 封禁后旧站内会话和关联 OAuth/OIDC 授权失效，密码或第三方登录均不能绕过；到期或解除后需要重新登录。
3. 检查公开原因、期限和历史记录；编辑框不显示管理员备注，修改其他字段不会清空既有备注。
   编辑框分成账号设置、徽章、限制记录三个 shadcn 标签页；切换标签保留未提交编辑，统一保存。常规内容在 1280×720 下完整显示；记录或徽章较多时允许内容区滚动，保存按钮保持可见，手机表单按单栏排列。
4. 管理员不能限制自己或移除最后一名可登录管理员；待强制邮箱验证的账号不计入可用管理员，取消邮箱验证状态、启用验证策略、角色删除、权限变更与封禁并发时仍保持该约束。

## 登录与安全日志

1. 覆盖密码、OAuth、MFA 成功和失败，以及密码、邮箱、MFA、账号限制变更。
2. 普通账号只能查看本人记录，不能通过传入其他用户 ID 读取他人日志；匿名登录失败仅管理员可查。
3. 核对基于 ID 的上一页、下一页和组合筛选；修改筛选或刷新回到第一页，不显示总条数或总页数。ID 间断、新增及删除记录不造成偏移重复；历史无结果字段的记录按成功兼容。日志不显示密码、验证码、恢复码或令牌，保留期为 90 天。
4. 日期筛选和账号限制期限均使用共享 shadcn 日历选择器；核对选中日期没有时区偏移，日志筛选可清除，限制期限可调整时间或设为永久。

## 注册与邮件闭环

先配置可用 SMTP；页面配置入口可从后台设置导航进入。配置存在只代表可以尝试发送，实际邮件送达仍需用测试邮箱验收。

1. 关闭注册后密码和 OAuth 新账号创建均被拒绝，已有账号登录及主动绑定保持可用。
2. 域名按精确匹配处理，`example.com` 不包含 `sub.example.com`；检查大小写、国际化域名及第三方未提供邮箱的情况。
3. 启用验证但 SMTP 未配置时拒绝创建待激活账号；上游可信的已验证邮箱可完成 OAuth 注册。
4. 需要邮箱验证时，注册成功返回登录表单和验证提示，不签发登录 Cookie 或普通会话。验证邮件激活成功后再登录；待验证账号的旧会话也不能继续使用。未激活账号用正确密码和验证码登录会触发重发，不获得普通会话。连续重试显示冷却或配额提示，邮件配置不可用或入队失败显示发送失败。重发成功表示已入队，实际 SMTP 交付需用测试邮箱确认。
5. 改邮箱时发送失败保留原邮箱和会话；SMTP 接受后切换到待验证状态、撤销旧会话，验证新邮箱后重新登录。
6. 将限额临时调低验证触发行为，再恢复设置。0 关闭对应限额。注册与邮件配额分别计数；反向代理必须正确配置可信代理。

## SQL 审查结论与验证边界

- 新增 SQL 与相关会话 SQL 封装在 `app/models/forum/` 的 `*_rep.go` 中；service 负责业务、缓存和必要的事务协调，controller 不拼接这些查询。
- 身份查重改用标准化 `username_key` / `email_key` 索引和 `LIMIT 1`，提及候选按索引前缀范围查询并限制数量；手输提及也按账号名索引批量查询，大小写处理在不同数据库中保持一致，历史重名账号不自动解析；提及通知批量处理，避免按用户逐一查询。
- 登录日志使用用户、结果、登录方式与 ID 的联合索引，以 ID 边界分页，不执行 `COUNT` 或 SQL `OFFSET`；时间索引用于筛选和清理。角色策略修改使用统一入口，只读取有关角色和授权；最后管理员检查使用存在性查询，限制历史按用户和 ID 索引分页。
- SQLite 查询计划测试覆盖主要索引和排序路径；没有进行生产数据量压测或真实 MySQL/PostgreSQL 执行计划、并发验证。日志的复杂组合筛选仍受过滤选择度影响，不能据此宣称任意规模下恒定耗时。
- 升级时分批回填身份索引字段，保留历史重复账号。身份写入互斥、注册配额和 MFA 挑战当前用于单实例，边界详见各功能文档。
- 前端桌面和手机交互测试使用测试 API 数据；真实 SMTP 投递、真实 OAuth 提供方回调和用户现场验收不能由这些测试替代。
