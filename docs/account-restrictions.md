# 账号限制

账号限制以 users.restriction_status、restriction_until、restriction_reason 和
restriction_note 为依据。旧数据中空状态 + IsFrozen=1 按永久禁言处理。

- normal：正常权限。
- suspended：可登录、阅读、管理密码/MFA/邮箱/外部绑定与会话；禁止受保护业务写入。
- banned：拒绝登录和会话认证，包括 OAuth、MFA 挑战和 OIDC 身份解析。
- restriction_until 留空为永久；到期按每次请求时间判断为正常，无定时任务。
- 原因可向本人公开；分页限制历史仅管理员可见。用户编辑框不提供管理员备注输入或展示，既有备注仍保留在管理员 API 和 CLI 中。

后台用户编辑使用限制服务；先单条更新账号，随后撤销 OIDC 凭据并补齐审计，不使用显式业务事务。部分失败会返回错误并刷新缓存，重新保存相同封禁状态仍执行幂等撤销；审计失败可在重试时补齐，重复保存相同记录不重复写入。
管理员保护为尽力检查，不使用全局角色锁；并发极端情况下可通过设置管理员 CLI 恢复。
限制自己、更高权限账号和最后一个有效管理员的操作被拒绝。管理员降权同样检查
最后管理员并撤销原会话。用户资料的通用保存不写入限制、角色、密码或令牌版本。

角色编辑和删除不使用显式事务或全局锁，逐步写入，失败时刷新缓存并返回错误，可重新编辑修复。非 Admin 的角色管理员只可管理
自身权限的子集，不能修改 Admin 角色，也不能给自己的角色增加额外权限。
删除或移除 Admin 角色权限必须保留其他正常管理员；与账号限制同时修改时仍保证
至少一个正常管理员存在的尽力检查。权限变化撤销该角色成员的旧会话，删除角色同时解除分配。

管理员必须在当前邮箱验证政策下可登录才计入保留数量。待验证且被强制验证的
账号不作为备用管理员；取消邮箱验证状态或启用全站邮箱验证时也必须保留至少
一个可用管理员的尽力检查。直接读取当前策略，不使用共享锁；并发极端情况下可通过 CLI 恢复。未强制验证的旧账号仍保留原兼容行为。

限制、角色权限、限制历史及 OIDC 撤销查询封装于对应 model 的 `*_rep.go`。
服务层协调必要的事务和业务权限判断。角色删除采用软删除，不使用全局角色行锁。
不要在在线管理流程物理删除角色记录；物理维护应离线进行。
每次权限检查只读取操作者与目标角色的授权；可能移除管理员时用 `LIMIT 1`
检查其他正常管理员，角色改名不读取成员。权限变化按角色批量更新令牌版本，
仅取成员 ID 用于提交后的缓存失效。限制历史按 `(user_id, id)` 索引分页。

封禁增加 TokenVersion，认证每次直接读取小型账号状态，不依赖展示缓存。
随后撤销本站 OIDC 的不透明访问/刷新令牌，并消费未兑换授权码。到期或解除
封禁不会恢复这些令牌；用户需要重新登录并授权。外部应用已经离线接受的签名 ID
Token 无法由本站远程撤回，应用仍须遵守令牌有效期。

在限制更新成功后开始的授权检查会拒绝受限操作；此前完成检查的在途请求可能
完成，不强制中断已获授权的请求。

账号限制统一通过后台用户管理操作。后台编辑必须提交 restrictionStatus，
新增 restrictionUntil/Reason/Note 字段，旧 status 数值只作为展示兼容字段。
