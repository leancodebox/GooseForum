# 访问控制性能基线

基准固定生成 100,000 个已发布主题和 100 个主分类，使用首页默认排序与 20 条分页，分别模拟 95%、50%、5% 分类可见率。受众条件直接作用在 `main_category_id`，不连接分类关系表；排序复合索引保持原列顺序。实测把主分类插入排序索引会让高可见率场景产生大范围分段扫描和额外排序，因此没有采用。

同一基准分别使用 SQLite 内存库和测试临时目录中的文件库。文件库会在测试结束后自动清理。

复现：

```bash
go test ./app/models/forum/topics -run '^$' \
  -bench '^BenchmarkAudienceTopicList100K(File)?$' \
  -benchtime=100x -count=5 -benchmem
```

2026-08-13，Apple M4，主分类标量过滤的 Go benchmark 结果。平均延迟是五轮 `ns/op` 的平均值；P95 是五轮各自 P95 的中位数：

| 存储 | 可见率 | 平均延迟 | P95 | 分配 |
| --- | ---: | ---: | ---: | ---: |
| 内存 | 95% | 0.276 ms | 0.295 ms | 51.3 KB / 1,412 allocs |
| 文件 | 95% | 0.283 ms | 0.318 ms | 51.8 KB / 1,416 allocs |
| 内存 | 50% | 0.275 ms | 0.287 ms | 46.1 KB / 1,321 allocs |
| 文件 | 50% | 0.286 ms | 0.299 ms | 46.6 KB / 1,325 allocs |
| 内存 | 5% | 0.450 ms | 0.466 ms | 40.6 KB / 1,227 allocs |
| 文件 | 5% | 0.468 ms | 0.482 ms | 41.2 KB / 1,231 allocs |

文件库的平均延迟比内存库高 2.4%～4.2%，P95 中位数高 3.3%～7.7%。文件库在写入种子数据后立即查询，数据库页通常仍在 SQLite 和操作系统缓存中，因此这是文件持久化路径的热缓存基线，不代表冷启动或物理磁盘随机读取延迟。

该基准不进入普通测试路径，避免每次 `go test ./...` 重建 10 万行数据。MySQL 的执行计划和 P95 应在实际部署版本、数据分布与连接参数下用同一查询补录；不能从 SQLite 数字外推。
