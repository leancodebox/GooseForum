# 注册限制

密码注册和 OAuth/OIDC 首次创建账号统一使用 `registrationservice`。注册关闭时，已有账号登录和主动绑定第三方账号继续可用。

## 配置

管理后台「安全」页设置每小时注册请求限额：每个可信 IP 默认 5 次，每个目标邮箱默认 3 次，全站默认 100 次。0 表示关闭对应限额。旧配置缺少这些字段时采用默认值，显式保存的 0 保留。

限额计数针对通过政策及凭据校验的注册请求，不是成功创建的账号数。密码注册在用户名、密码和验证码校验通过后才消耗配额，无效验证码不能耗尽全站注册限额；OAuth/OIDC 在上游身份验证通过并满足注册政策后计数。计数器使用单进程内存，窗口从第一次请求起持续一小时，最多保存 10000 个桶；容量耗尽时拒绝新桶，过期后释放。重启清空，不提供多实例共享计数。

密码重置和验证邮件共享独立邮件配额：每个 IP 每小时 20 次，每个邮箱 3 次，全站 200 次。验证邮件重发仍保留已有每分钟一次、每天三次的账号限制。

反向代理部署需在 `config.toml` 的 `[server].trustedProxies` 设置代理 IP 或 CIDR，
才能使用代理传递的客户端 IP。默认空列表不信任转发头；未配置时限额会按代理本身
的 IP 统计，不要把任意来源设为可信代理。

## 邮箱政策

允许域名按小写和 IDNA 规范化，精确匹配。`example.com` 不允许 `sub.example.com`；没有隐式通配或后缀匹配。

OAuth 新账号需要邮箱时，上游没有给出有效邮箱则拒绝创建，用户可先用邮箱注册再主动绑定。上游邮箱未验证时，由本站发送验证邮件。要求验证或配置允许域名的账号会保存独立验证要求，切换登录入口或关闭后续注册验证不能绕过。第三方邮箱与已有账号冲突时拒绝创建，不自动绑定。

创建需要本站验证的新账号之前检查邮件配置，未配置 SMTP 时拒绝创建，避免留下无法激活的账号。可信上游已验证的邮箱不需要本站发送验证邮件。待激活账号通过正确密码和验证码再次登录时触发验证邮件重发，不建立普通登录会话；重发仍遵守冷却和配额，失败可在恢复邮件服务后重试。

旧账号没有独立验证要求的标记，继续遵循旧验证开关，以免关闭验证的站点把历史账号意外锁住。

网页改邮箱先检查邮件配置并同步发送验证邮件，SMTP 接受后才更新邮箱、设为待验证并
撤销旧会话。发送失败保留原账号状态；SMTP 接受不代表邮件一定送达。

## 并发与数据库兼容

用户名、邮箱创建和修改使用同一个进程内身份写锁，并在写入前按大小写无关规则再次查重。第一位管理员仍基于数据库生成的用户 ID 1，不通过账号计数竞争判断。

用户名、邮箱去除首尾空格并转小写后直接存入原字段，由唯一索引保证并发写入不重复；无邮箱存为 NULL。查重使用原字段的存在性查询，避免对整列执行 LOWER 与计数。普通资料保存不能覆盖身份字段，不使用全局身份锁。已删除账号的身份仍被保留。

OAuth 新账号和登录绑定在同一事务中创建，绑定失败会回滚账号。下载头像与保存展示资料放在创建之后。

历史用户表和 OAuth 表可能含重复数据，本版没有强行添加唯一索引，也不自动删除重复账号。因此身份写入保证的范围是单实例；多实例部署需要先清理历史重复，并设计数据库唯一约束或共享身份写入策略。
